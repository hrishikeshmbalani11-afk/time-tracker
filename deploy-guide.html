Version Control — Git & GitHub

Turn your project folder into a tracked repository and push it to GitHub.

1.1 Open a terminal in your project folder and initialize Git. 
cd "C:\Users\hrish\OneDrive\Documents\vibe codes\Time Tracker"
git init
git add .
git commit -m "Initial commit — TimeFlow PWA"
💡 The generate-icons.html utility file is harmless to include, but if you want a clean repo you can add it to a .gitignore before committing.
1.2 Create a new repository on GitHub:
Go to github.com/new → Name it timeflow → Leave it Public (required for free Vercel) → Do not add a README (you already have one) → Click Create repository.
1.3 Link your local repo to GitHub and push. 
git remote add origin https://github.com/<your-username>/timeflow.git
git branch -M main
git push -u origin main
⚠ If you haven't authenticated Git with GitHub yet, run gh auth login (GitHub CLI) or set up an SSH key / personal access token first.
2
Deploy on Vercel

Vercel's free Hobby tier gives you HTTPS, a global CDN, and instant deploys — perfect for a static PWA with no build step.

2.1 Go to vercel.com and sign up with your GitHub account.
2.2 Click "Add New…" → Project. Find and select your timeflow repository from the list. Grant Vercel access if prompted.
2.3 On the Configure Project screen, leave everything as default — no framework, no build command, no output directory. Vercel serves static files from root automatically.
2.4 Click Deploy. In ~30 seconds, your site is live at:
https://timeflow-<hash>.vercel.app
✓ Your PWA is now live with HTTPS (required for Service Workers), a free .vercel.app domain, and a global edge network. Open it on your phone and tap Add to Home Screen.
2.5 Optional — custom domain. In the Vercel dashboard → your project → Settings → Domains, add a domain you own. Vercel provisions a free SSL certificate automatically.

Continuous Deployment

This is already set up. Vercel watches your GitHub repo — every push to main triggers a new production deploy.

Edit code → git push → GitHub → Vercel webhook → Live in ~20s
3.1 Make a change, commit, and push. Watch Vercel auto-deploy. 
# Example: tweak and redeploy
git add .
git commit -m "Update chart colors"
git push
💡 Preview deploys: Push to any branch other than main, and Vercel creates a unique preview URL. Useful for testing changes before they go live.
3.2 Service Worker cache-busting. When you update the app, bump the cache version in sw.js so returning visitors get the new files. 
// sw.js — change 'v1' to 'v2' (or higher) after updates
const CACHE_NAME = 'timeflow-v2';

Firebase Security

Your API key being visible in frontend code is expected by Firebase's design. The key alone can't read or write data — that's controlled by Firestore rules and API key restrictions. Here's how to lock both down.

🔒 Do not skip this. The default "test mode" rules allow anyone on the internet to read, write, and delete all your data. The steps below cut access to only you, on only your domain.

A. Enable Firebase Authentication

4.1 In the Firebase Console, go to your project → Authentication → Get started.
4.2 Enable the Google sign-in provider (easiest for single-user). Toggle it on, select your email as the support email, and click Save.
4.3 Under Authentication → Settings → Authorized domains, add your Vercel domain:
timeflow-<hash>.vercel.app
Remove localhost once you're done testing.

B. Lock Down Firestore Rules

4.4 Go to Firestore Database → Rules and replace the default rules with this. It allows only your signed-in account to read or write.
firestore.rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {

      // Replace with YOUR Firebase UID (step 4.6)
      allow read, write: if request.auth != null
        && request.auth.uid == "PASTE_YOUR_UID_HERE";

    }
  }
}
4.5 Click Publish to apply the rules immediately.
4.6 Find your UID: Go to Authentication → Users tab. Sign in to your app once (after adding the auth code below), and your UID will appear in the table. Copy it back into the rules above.
💡 With this rule, even if someone extracts your API key, every read and write is rejected unless they are signed in as you. The key is useless without your Google account session.

C. Add Sign-In to TimeFlow

4.7 Add Firebase Auth to your app. In app.js, update the initFirebase() function to load the auth SDK and sign in with Google before initializing Firestore listeners. 
// Inside initFirebase(), after loading the firestore script:
await loadScript(
  'https://www.gstatic.com/firebasejs/10.12.2/firebase-auth-compat.js'
);

const app = firebase.apps.length
  ? firebase.app()
  : firebase.initializeApp(config);

// Sign in with Google (popup)
const auth = firebase.auth();
if (!auth.currentUser) {
  const provider = new firebase.auth.GoogleAuthProvider();
  await auth.signInWithPopup(provider);
}

// Now initialize Firestore (existing code continues here)
firebaseDB = firebase.firestore();
⚠ On mobile, signInWithPopup may be blocked. Use signInWithRedirect(provider) and getRedirectResult() on page load as a fallback for reliable mobile auth.

D. Restrict the API Key

4.8 Go to Google Cloud Console → APIs & Services → Credentials. Find the Browser key auto-created by Firebase (named "Browser key (auto created by Firebase)").
4.9 Click the key → Application restrictions → select HTTP referrers (websites). Add your allowed domains: 
timeflow-*.vercel.app/*
your-custom-domain.com/*
localhost:*/*
4.10 Under API restrictions → select Restrict key → allow only these APIs: 
Cloud Firestore API
Identity Toolkit API
Token Service API
4.11 Click Save. The API key now only works from your domain and only for the Firebase services you actually use. Even if someone copies it, requests from any other origin are rejected by Google's infrastructure.
✓ You're now triple-protected:
1. Firestore rules — only your UID can read/write
2. Auth — only your Google account can obtain that UID
3. API key restriction — key only works from your domain
